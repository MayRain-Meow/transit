# Agent Note: 竖屏地图旋转与竖屏特化（基于 0.5）

Status: implemented

## Problem

用户验收 0.4.1 后反馈：底栏过高、地图不适合竖屏、新地点交互手感差、线路端点延长手感差、冗余功能多。上游随后发布 0.5（城市活动、新城 30 秒自动开放），用户要求合并后再按竖屏优化地图、事件标记、地形和字体的观感。

审计结论：

- 世界是 1200×710 的横向地图，新城只出现在 `y 265–620` 的横向带内（约 2.4:1），竖屏可用区域约 0.6:1。无论怎么取景，城市都挤成中间一条细带。
- 竖屏底部被两块占据：线路面板（约 150px）和 58px 的底部按钮栏，合计约 240px。
- 远城出现时 `spawnCity` 会调用 `fit()`；旧的 `tick` 在新城出现于屏幕外时会 `animateFit()`。两者都会把镜头拉走。
- 延长线路要先选中线路再拖端点城市，一次只能接一座城；多线共用的城市会先弹出选线面板。
- 运营中心的标题被 0.5 的活动区块挤到下方，「城市任务」「收支账本」与底部按钮栏、顶栏资金入口重复。工程面板对每座城市都列「建气象站 / 枢纽 / 检修中心」，与城市详情里的按钮重复。帮助末尾追加了大段版本说明。
- 上游的「撤回建线」浮条（`z-index:45`）会盖住弹窗和顶部通知。

## Decision

用户选择「竖屏旋转 90°」（另一个选项是保持方向、只调整取景）。

- **引擎（game.js）**
  - 新增 `view.rot`：竖屏为 1，顺时针旋转 90°，海在下方，北岭在右侧。
  - `toWorld` 支持旋转；新增 `toScreen`。`render` 统一施加旋转，零散的屏幕坐标计算全部改用 `toScreen`。滚轮缩放改为按屏幕空间锚定，与旋转无关。
  - `text()`、`roundBody()` 读取当前变换矩阵：旋转时绕自身锚点转回正立。城市装饰整组绕城市中心转正（`uprightAround`），建筑和树用 `uprightHere`。
  - 地形缓存分横、竖两份；竖屏单独画朝上的层叠山峰，海浪改为水平走向。
- **取景（world.js）**：`fit()` 在旋转时交换横竖跨度。越界回弹改为屏幕空间判断。远城出现时不再自动取景。
- **体验层（ux.js）**
  - **城市附属标签**：任务角标、活动/商演标记、学校/检修图标、开放倒计时，按「80 单位内最近城市；否则正下方 150 内的城市」找到所属城市，再绕它转正（城市间距至少 145）。这些包装在 `DOMContentLoaded` 后挂上，因为 `events.js` 在 `ux.js` 之后加载。
  - **端点把手**：每条线路两端各有一个把手，选中的线路高亮。从把手拖出可连续接多座城，回拖可撤回；不需要先选线，多线城市也不弹选线面板。点一下把手不拖动 = 选中线路。
  - **屏幕边缘指示**：屏幕外的待开放新城（带倒计时）和告急城市显示在边缘，点一下平滑移过去并打开城市面板。镜头不再自动移动。
  - **标签与字体**：缩小查看时标签字号最多放大 1.35 倍；画布文字改用 Noto Sans SC。
  - **面板整理**：运营中心标题置顶并删除重复入口；工程的逐城设施列表合并为一行汇总；帮助里的版本说明收进「版本新增」折叠组。
- **CSS（竖屏）**
  - 线路面板变成一行可横向滑动的线路胶囊，配「＋」和「⌖」两个按钮；底部按钮降为 50px，底部区域总高约 120px。
  - 隐藏横屏建议和顶栏里的维护预估。
  - 「撤回建线」浮条移到通知下方居中，弹窗打开时隐藏。

## Alternatives considered

- **保持方向、只调取景**：仍然是一条横带，需要频繁左右拖动，用户未选。
- **按竖屏重新生成世界**：会改变地形、平衡和存档语义，不采用。
- **旋转时交换城市坐标、不旋转画布**：地形函数（`river(y)`、山体判定）依赖真实坐标，渲染期间临时交换坐标容易出错。
- **把附属标签函数整段复制成竖屏版**：会随上游改动而漂移；现在用「执行期间临时替换 `text` / `roundBody`」的包装，上游改动后无需同步。

## Consequences

- 新增屏幕坐标计算一律用 `toScreen` / `toWorld`，不要手写 `x*view.scale+view.x`。
- 新的「城市 + 偏移」绘制函数，如果要在旋转下保持正立，需要加进 `uxWrapLateDrawers` 的名单，或直接接收城市参数后使用 `uprightAround`。
- 地形缓存键为 `terrainCache[0|1]`，把 `terrainCache` 置为 `null` 会同时失效两份。

## Follow-up: 竖屏体验重做——车辆朝向、可读取景、延长入口；合并 1.0（2026-11-05）

基线 `e7a5761`。上游在实现过程中发布了 1.0（`73adc6b`），已在本地合并。按要求只做本地实现与验证：未推送、未建 PR、未合并到上游、未部署。

### 1. 车辆朝向（P1）
- **原因**：`roundBody()` 通过 `ctxRotated()` 判断要不要把内容「转正」，而 `ctxRotated()` 读的是累计变换矩阵。`drawVehicle` 已经先按航向旋转过画布，只要「地图旋转 + 车辆航向」合起来接近 ±90°，车身、色带和车窗就会被再转 −90°，车轮（`ctx.roundRect`）却不受影响。结果竖屏斜向或竖向线路上的大巴、列车横置；横屏竖向行驶的车辆同样出错（自 `83627cc` 起的回归）。
- **修复**：`ctxRotated()` 只在地图确实旋转（`view.rot=1`）且不处于局部坐标作用域时返回 true；`drawVehicle` 进入局部作用域（`localFrameDepth`），车身、车窗、车轮和车厢统一跟随线路航向。城市、标签的正立逻辑不变；横屏永不补偿。
- **验证**：
  - 改前改后连续帧（竖屏 390×844、横屏 844×390；大巴、动车、高铁、飞机），见 `artifacts/portrait-v3/01-02`。
  - E2E 中按实际运动方向逐辆比对航向，最大偏差 0°。
  - 回归测试「vehicles follow their heading」：在旧代码上记到 4 次错误转正。

### 2. 竖屏画面过小
- **原因**：
  - 存档默认视图要把全部城市（含远城）塞进屏幕，390×844 下缩放 0.557、城市节点半径约 6.7px，360×740 下缩放 0.467；
  - 留白用固定世界单位（±150/140）；
  - 线路、节点、地名都随地图一起缩小。
- **修复**：
  - **取景**：`fit()`（全图）四周留白改为屏幕像素（左 34、右 86、上 44、下 58）。新增「游玩视图」`uxPlayTarget`：只看已开放城市，缩放下限 0.66，放不下时选覆盖城市最多（有线路的计 2 分）的窗口。开局、继续存档和窗口尺寸变化时使用游玩视图；⌖ 在游玩视图与全图之间切换。
  - **尺寸层级**：`CITY_GLYPH`（节点、地名、状态、候车方块作为一组，最多放大 1.45 倍）和线宽下限（最多 1.4 倍）；建筑不放大。文字补偿改为按实际变换缩放，避免与组放大叠加。
  - **开关详情不累积缩小**：自动取景记录「打开前的视图」和每次动画目标（`animateView` 记录 `uxLastViewTarget`）；关闭面板时，如果视图仍停在自动取景的位置，就恢复到打开前；用户拖动或缩放过则保留用户的视图。拉线或延长导致面板收起时不恢复（否则地图会在手指下跳动）。竖屏下 `openCity` 不再先 `panTo`，统一交给面板取景。
  - **浮层**：竖屏通知压成一行（超出省略）；全展开时通知和边缘提示淡出，面板上方的空隙留给选中城市。
- **数据**（同一存档、同一视口）：
  - 390×844：0.557→0.66（节点视觉半径约 6.7→10px）；
  - 360×740：0.467→0.66；
  - 新游戏：0.85→1.15。
  - 连续开关详情、切换城市和线路，缩放保持 0.66。截图见 `03-04`。

### 3. 线路延长入口（原端点把手）
- **原因**：每条线路两端常驻白色圆环把手，浏览时有 8 个控件同时显示且都能被点中，看起来像多出来的车站。
- **设计**：
  - 浏览态不绘制也不命中；
  - 选中线路后，两端出现同色短引线加带「＋」的圆形标签，刚选中时脉动一次提示可拖；
  - 触控半径 22px（约 44×44 CSS px），落在端点城市节点上时优先算城市；
  - 标签会避开候车方块；
  - 轻点「＋」不拖动时提示拖法；
  - 线路面板文案改为「拖动线路两端的 ＋ 可连续延长」。
- **随之修复**：
  - 边缘自动平移只在手指离开起点 24px 后生效（标签靠近屏幕边缘时，按下即滚屏会导致错位）；
  - 屏幕外指示条压住屏幕上的城市时，会沿边滑开，找不到空位就暂不显示。此前点城市可能点到指示条，被带去远城。
- 截图见 `05`。
